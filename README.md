# Codex Usage Sentinel

Windows-программа, которая раз в минуту читает лимиты локального Codex и отправляет уведомления в выбранный чат Telegram. **Build 1.6.1: тихий статус только с процентами и звуковые будильники; личный чат или группа. На GitHub только исходники. Автозапуска нет.**

**[Скачать исходники ZIP](https://github.com/antonstrobe/codex-usage-sentinel/archive/refs/heads/main.zip)** · **[Короткая инструкция для нового пользователя](docs/SECOND_COMPUTER.md)** · **[Инструкция для Codex](docs/SETUP_WITH_CODEX.md)**

## Как начать

1. Установите Codex для Windows и войдите в свой ChatGPT-аккаунт.
2. Скачайте ZIP, распакуйте проект в постоянную папку, например «Документы». Откройте эту папку как проект в Codex.
3. Напишите Codex:

> Прочитай AGENTS.md и docs/SETUP_WITH_CODEX.md. Проверь исходники Codex Usage Sentinel, собери и проверь локальный EXE, затем запусти программу в трее без автозапуска. Помоги подключить мой Telegram и проверить мои лимиты. Секреты вводятся только локально. Если Defender обнаружит угрозу, остановись и сообщи результат проверки.

4. В меню значка около часов выберите **Открыть** для настройки Telegram и будильников. После настройки окно можно закрыть: монитор останется в трее.

После перезагрузки откройте тот же проект и напишите: **«Запусти Codex Usage Sentinel в трее»**. Если исходники не менялись и проверенный EXE сохранён, повторная сборка не нужна. Программа работает самостоятельно после запуска, даже когда диалог с Codex завершён. **Выйти** в меню трея полностью останавливает монитор; выключение или выход из Windows тоже его завершает. Во сне проверки не выполняются.

EXE создаётся в `dist/CodexUsageSentinel.exe` на вашем компьютере. На рабочий стол и в папку автозагрузки ничего переносить не нужно. Программа не создаёт ярлыки, записи Run, задачи планировщика или службы. На GitHub готовые EXE и архивы с ними больше не публикуются.

## Telegram

**Общий бот через Start пока недоступен: сервис не установлен.** Для него оператор должен отдельно развернуть [сервис общего бота](docs/SHARED_BOT.md), разрешить ваш username и передать рабочий HTTPS-адрес. Затем **Telegram… → Подключить через Start** создаст личную ссылку. Обычный Start без ссылки из программы компьютер не подключает. Токен общего бота пользователям не передаётся.

Для самостоятельной настройки доступен **Telegram… → Настроить своего бота…**: токен собственного бота, ваш username и Start в его личном чате. При необходимости укажите числовой ID своего личного чата. Вводите токен в защищённое поле окна программы, не в чат Codex и не в репозиторий. Токен хранится через Windows DPAPI для текущего пользователя. [Требования Telegram](https://core.telegram.org/bots/api).

**Лично мне / В группу** выбирает единственного получателя всех автоматических уведомлений и тестов. Активный вариант зелёный с галочкой; строка «Получатель» показывает текущий чат. Выбор сохраняется после перезапуска. Личный адрес и группа хранятся отдельно, поэтому можно переключаться обратно без повторного ввода. Ошибка группы не вызывает отправку в личный чат. Уже переданный Telegram запрос ещё может завершиться после переключения; ожидающий отправки запрос прежнему получателю отменяется.

Для группы нужен бот с токеном, настроенным на этом компьютере: добавьте его в группу, нажмите **В группу → Найти группы**, выберите нужную и **Проверить и выбрать группу**. Если список пуст, отправьте в группе `/start@имя_вашего_бота` и повторите поиск либо введите отрицательный Chat ID. Программа проверяет тип чата и права бота на отправку; канал и личный чат вместо группы не принимаются. Правая кнопка на **В группу** или пункт **Настроить группу…** в трее позволяет заменить группу. При смене токена сохранённая группа сбрасывается для повторной проверки. Relay через Start пока поддерживает только личный чат; групповой режим использует прямое подключение.

**Проверить сейчас** читает лимиты. **Тестовое сообщение** отправляет одно сообщение в выбранный чат; правая кнопка или Shift+F10 открывает серию из десяти с интервалом не менее двух секунд. Это разовое действие. Пауза автоматических уведомлений не мешает ручному тесту. Звук зависит от настроек Telegram и телефона.

## Тихий статус с процентами

Включите **Тихий статус** в главном окне. В выбранном чате появится одно сообщение без звука, содержащее только число и знак процента, например `34%`. Оно обновляется после проверки лимитов, обычно каждую минуту, независимо от порогов будильников. При ошибке чтения или отсутствии свежих данных показывается `—%`. Пауза будильников не останавливает тихий статус.

После сообщения будильника, теста или предупреждения о связи программа публикует новый тихий статус ниже него и удаляет предыдущий статус. Будильники остаются в истории. Между событиями используется редактирование существующего сообщения. Telegram не переносит отредактированное сообщение в конец чата; поэтому для перемещения вниз требуется новая отправка. Сообщения других участников могут оказаться ниже статуса — программа их не отслеживает и не удаляет.

Создание статуса без звука использует `disable_notification=true`, обновление — `editMessageText`. Будильники и ручные тесты сохраняют обычный звук (`disable_notification=false`), если звук разрешён настройками Telegram и телефона. Дополнительная тихая отправка увеличивает фактический интервал между звуковыми сообщениями: общий минимум 2 секунды соблюдается для всех отправок. [Telegram Bot API](https://core.telegram.org/bots/api#editmessagetext).

ID сообщения сохраняется в LocalAppData в `status-messages.json`; перезапуск продолжает обновлять его. Для разных получателей сохраняются отдельные ID, обновляется только выбранный чат. При выключении программы в чате остаётся последнее значение; до следующего запуска оно не обновляется. Статус доступен для прямого подключения бота; серверный relay пока его не поддерживает.

Если статус удалили, программа создаст новый без звука. При неподтверждённом результате создания она остановит повторные создания, чтобы не насыпать дубликаты. Правая кнопка или Shift+F10 на переключателе → **Создать статус заново** разрешает новую попытку; неизвестное старое сообщение может остаться. Если Telegram запретил удаление прежнего статуса, сообщение об этом появится в окне, а старый статус может остаться в истории. Выключенный или спящий компьютер ничего не обновляет.

## Будильники по процентам

Откройте **Будильники… → + Добавить**: процент оставшегося лимита (0–100%), количество сообщений (1–10000) и интервал (от 2 секунд до 24 часов). **Непрерывный повтор** включает отправку до восстановления процента выше порога. **Открыть…** или двойной щелчок изменяет событие; **Удалить** убирает его. Включённый будильник отмечен зелёным и галочкой.

**Сохранить** применяет изменения; **Отмена** сохраняет прежнее состояние. Удаление или отключение отменяет оставшуюся серию; уже переданный Telegram запрос ещё может завершиться. Если порог достигнут, новое, изменённое или повторно включённое правило может начать серию сразу. Пустой список отключает уведомления по процентам.

Правила с одинаковым процентом работают независимо. При перескоке нескольких разных порогов самый низкий отменяет более высокие серии в том же окне лимитов. После восстановления процента выше порога правило готово к новому снижению. Интервал отсчитывается от завершения отправки; очередь сохраняется после перезапуска.

Начальные события: **10% → 10 сообщений; 5% → 10; 3% → 50; 2% → непрерывно**, интервал 2 секунды. Пауза отключает автоматические уведомления на 30 минут, сохраняя проверку лимитов. Зелёная кнопка с галочкой показывает включённую паузу.

Устаревшие данные не вызывают рассылку. После трёх ошибок чтения отправляется одно предупреждение о связи. Дополнительные лимиты вроде Spark показаны справочно. Программа не покупает и не применяет сбросы. При аварии в момент отправки возможен повтор одного сообщения; задержка Telegram `retry_after` соблюдается.

## Defender

В версии 1.1.0 зарегистрировано обнаружение **Behavior:Win32/DefenseEvasion.A!ml**. Причина пока не установлена. Удаление автозапуска и сборка из исходников **не доказывают**, что обнаружение исправлено; запуск через Codex также не даёт исключения из проверки антивирусом.

При новом обнаружении не запускайте заблокированный файл, не отключайте защиту и не добавляйте исключения. Не пересобирайте или переименовывайте файл ради обхода блокировки. Сохраните название обнаружения, версию и SHA-256 для расследования. Microsoft предлагает [отправить подозрительный или ошибочно обнаруженный файл на анализ](https://learn.microsoft.com/en-us/defender-xdr/developer-faq); отправка выполняется отдельно владельцем файла. Чистое сканирование и успешные тесты не исключают поведенческого обнаружения при работе.

## Сборка и запуск

Нужны Windows 10/11, .NET Framework 4.8 с штатным C# compiler и локальный `codex.exe` с выполненным входом. NuGet не требуется. В PowerShell из папки проекта:

```powershell
.\build.ps1
.\test.ps1
.\verify-release.ps1
.\start.ps1
```

`start.ps1` запускает уже собранный локальный EXE в трее, без пересборки и изменений автозапуска. `start.ps1 -Show` открывает настройки. Если файл отсутствует после обнаружения антивирусом, сначала разберите причину. Повторный запуск использует один экземпляр программы на пользователя Windows.

GitHub Actions собирает и проверяет исходники, включая тесты relay и сканирование, но не загружает EXE в артефакты или Releases. Контрольная сумма локальной сборки находится в `dist/SHA256SUMS.txt`.

## Данные и прежние установки

Настройки и очередь хранятся в `%LOCALAPPDATA%/CodexUsageSentinel/`. Не переносите `settings.json`, `alerts.json`, `status-messages.json`, токены, ключи устройства или авторизацию Codex между компьютерами. На новом ПК настройте собственное подключение. Авторизация Codex остаётся в его штатном локальном хранилище.

Если прежде включали автозапуск, удалите старую запись **CodexUsageSentinel** в автозагрузке и только относящиеся к этой программе EXE/ярлыки из `shell:startup`. Codex может помочь проверить точные пути по [инструкции](docs/SETUP_WITH_CODEX.md). Обновлённый EXE сам не изменяет прежние настройки Windows.
