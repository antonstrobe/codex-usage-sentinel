# Инструкция для Codex на Windows

Цель: по просьбе пользователя собрать локальный EXE из исходников и запустить монитор в трее до выхода из программы или завершения сеанса Windows. **Автозапуск, службы, планировщик и ярлыки не создавать.** Не привязывай время работы монитора к окончанию ответа Codex: после запуска он работает самостоятельно.

## Первая установка

1. Прочитай `AGENTS.md`, README и `docs/SECOND_COMPUTER.md`. Работай в распакованном проекте; не используй чужие EXE или настройки. Проверь Windows, .NET Framework 4.8 и доступность штатного `csc.exe`.
2. Найди локальный `codex.exe` через PATH или `%LOCALAPPDATA%/OpenAI/Codex/bin/*/codex.exe`; в программе доступна кнопка **Codex CLI…**. При отсутствии входа попроси пользователя войти в свой аккаунт через интерфейс Codex. Не читай и не копируй `auth.json`, cookie или токены OpenAI.
3. Прочитай относящиеся к запуску исходники. Выполни `build.ps1`, `test.ps1`, `verify-release.ps1`. Результат — `dist/CodexUsageSentinel.exe`; оставь его в проекте. Не создавай Build.exe, ярлыки или копии на рабочем столе. Не меняй системные политики исполнения скриптов.
4. Учти известное обнаружение Defender в 1.1.0: причина не установлена, 1.4.0 не объявлена исправлением. При доступном Defender проверь локальный файл штатным сканированием; если обнаружение относится к этому файлу или сборке, остановись и сообщи детали. Не восстанавливай карантин, не добавляй исключения и не пересобирай ради обхода обнаружения. Чистое сканирование не гарантирует безопасности поведения.
5. При отсутствии блокировки проверь чтение лимитов отдельной диагностикой. `--probe` не отправляет Telegram и не расходует сбросы. Пример из папки проекта:

```powershell
$probePath = Join-Path $env:TEMP ('codex-usage-probe-' + [Guid]::NewGuid().ToString('N') + '.json')
$localExe = Join-Path $PWD 'dist\CodexUsageSentinel.exe'
$probeProcess = Start-Process -FilePath $localExe -ArgumentList @('--probe', ('"' + $probePath + '"')) -WindowStyle Hidden -PassThru -Wait
try {
    if ($probeProcess.ExitCode -ne 0) { throw 'Codex limits probe failed.' }
    Get-Content -LiteralPath $probePath -Encoding UTF8
} finally {
    if (Test-Path -LiteralPath $probePath) { Remove-Item -LiteralPath $probePath }
}
```

6. Запусти `start.ps1` для трея или `start.ps1 -Show` для настройки. Проверь точный путь процесса, Build и свежесть лимитов. Успех Start-Process означает только запрос запуска; проверь, что монитор остался работать. Если он уже запущен, второй экземпляр не создаётся.
7. Для общего бота сначала проверь наличие рабочего HTTPS-адреса от оператора. **Сервис пока не развёрнут. Не утверждай, что Start уже подключает пользователя, не придумывай адрес и не устанавливай сервер без отдельного разрешения.** После развёртывания введи URL, username и имя ПК; пользователь нажимает Start по личной ссылке из программы. Для собственного бота секрет вводит пользователь только в защищённом поле. Не меняй чужой webhook/getUpdates.
8. Реальные тестовые сообщения отправляй только по просьбе пользователя. Проверь выбранные будильники, объясни кнопки паузы и выхода. Оставь основной монитор работать по запросу; закрой временные тестовые процессы.

## После перезагрузки

По сообщению **«Запусти Codex Usage Sentinel в трее»** открой этот проект и выполни `start.ps1`. Если исходники не менялись и проверенный EXE сохранился, не пересобирай. Если EXE отсутствует, выясни, был ли он удалён защитой; блокировку сначала расследуй. После обновления исходников повтори сборку и проверки. Перед заменой работающего EXE проверь PID и полный путь, останови только этот монитор.

Окончание диалога с Codex не останавливает программу. После выхода из Windows или перезагрузки пользователь сам снова просит запуск. Во сне компьютер не проверяет лимиты.

## Переход со старого автозапуска

Если пользователь просит убрать прежний автозапуск, проверь **только** значение `CodexUsageSentinel` в `HKCU/Software/Microsoft/Windows/CurrentVersion/Run`. Сверь его команду с точным EXE этого проекта, сохрани прежнее значение в локальной резервной копии и удали эту запись. В `shell:startup` удаляй только подтверждённый EXE или ярлык этого монитора, проверяя назначение ярлыка. Остальные записи, программы и задачи не трогай. Новый EXE не правит реестр и не удаляет старый автозапуск автоматически.

## Интеграция и файлы

Монитор запускает `codex.exe app-server` через stdio и выполняет JSON-RPC `initialize`, `initialized`, `account/rateLimits/read`. Это чтение лимитов, без задачи модели и сетевого слушающего порта. Остаток — `100 - usedPercent`, в пределах 0–100; основной bucket `codex` в `rateLimitsByLimitId`, запасной формат `rateLimits`. Отсутствие данных означает неизвестный статус. [Документация App Server](https://learn.chatgpt.com/docs/app-server).

| Файл | Назначение |
| --- | --- |
| `src/Core.cs` | настройки, DPAPI, чтение Codex |
| `src/Alarms.cs`, `src/AlarmForms.cs` | правила, очередь и редактор будильников |
| `src/Monitor.cs` | Telegram и цикл мониторинга |
| `src/App.cs` | окно, трей, один экземпляр, параметры запуска |
| `src/RelayClient.cs`, `src/RelaySetupForm.cs` | подключение общего бота |
| `relay/` | серверные исходники, конфигурация-пример, тесты |
| `src/Version.cs` | номер Build |
| `build.ps1`, `start.ps1` | локальная сборка и ручной запуск |
| `test.ps1`, `src/Tests.cs` | проверки без реальных сообщений |

Параметры EXE: `--tray` — тихий запуск; `--show` — открыть окно; `--probe <путь.json>` — однократное чтение лимитов; `--render <путь.png>` — диагностика отрисовки. Настройки и очередь лежат в LocalAppData вне проекта. Не выводи их содержимое и не добавляй в Git, даже зашифрованными.

На GitHub публикуются только исходники. CI может собирать и проверять EXE внутри временного runner, но не должен выгружать бинарники в Releases, Git или Actions artifacts. Сервис общего бота не устанавливать без отдельного разрешения оператора.
