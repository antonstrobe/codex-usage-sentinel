# Сервис общего Telegram-бота

**Статус: подготовлены только исходники. Сервис не установлен и публичного рабочего адреса нет.** Для подключения через Start требуется отдельное развёртывание оператором. Текущий релиз EXE 1.1.0 этот режим не поддерживает.

`relay/relay.py` — отдельный Python 3.10+ сервис без внешних зависимостей. Он работает на loopback за HTTPS Nginx. Проверка Codex остаётся на Windows; сервис не получает авторизацию OpenAI и не выполняет сбросы.

## Привязка

1. EXE генерирует случайный 256-битный ключ устройства; передаёт сервису только SHA-256 вместе с username и именем ПК.
2. Сервис выдаёт одноразовую ссылку `https://t.me/<bot>?start=c_<id>` на 10 минут.
3. Один серверный getUpdates принимает Start только из личного чата указанного пользователя. Первое подтверждение закрепляет Telegram ID; смена владельца username не заменяет закреплённый ID.
4. EXE проверяет результат с Bearer-ключом и сохраняет ключ через DPAPI CurrentUser. Токен бота клиенту не выдаётся.
5. Уведомления аутентифицируются ключом устройства. Сервер выбирает привязанный чат; передача `chat_id` в API запрещена.

Ссылка Start создаётся на подключаемом компьютере. Не пересылайте чужие ссылки. Владелец разрешает пользователей в `allowed_users`; для известных пользователей укажите числовой Telegram ID заранее, иначе `0` закрепит ID при первом Start. Изменяемый username до первого Start сам по себе не доказывает личность человека.

## Размещение оператором

Пример путей в unit:

- `/opt/codex-usage-relay/relay.py` — код, root-owned, чтение сервисному пользователю.
- `/etc/codex-usage-relay/config.json` — приватная конфигурация root:codex-usage-relay, `0640`.
- `/var/lib/codex-usage-relay` — SQLite и состояние; сервисный пользователь, `0700`.
- `/etc/credstore.encrypted/codex-usage-relay.cred` — токен, зашифрованный `systemd-creds`, `0600`. `LoadCredentialEncrypted` выдаёт его только сервису.

Конфигурация содержит `bot_username`, `allowed_users` (отображение username → Telegram ID, `0` для первого Start), необязательные `port` и `database`. Не коммитьте рабочую конфигурацию, SQLite или credential-файл. Токен передавайте `systemd-creds encrypt --name=telegram-token - <credential-path>` через защищённый stdin; не помещайте в командную строку, историю или обычный текстовый файл.

Перед установкой согласуйте конкретный сервер, убедитесь в отсутствии другого getUpdates/webhook и свободном порте. Код при наличии webhook останавливается, не меняя его. Ошибка Telegram 409 останавливает poller с видимым отказом; другую интеграцию автоматически не перенастраивает.

Создайте отдельного системного пользователя без shell, установите `relay/codex-usage-relay.service`. `relay/nginx-http.conf` подключается один раз в http-контекст; `relay/nginx-location.conf` — только в выбранный virtual host. Проверьте `nginx -t` перед reload. Другие сайты, VPN и сервисы менять не требуется. При обновлении сначала сохраняйте резервную копию изменяемых файлов. После размещения передайте пользователю HTTPS-адрес с префиксом `/codex-usage`.

`GET /health` отвечает 200 только при недавнем успешном чтении Telegram; 503 означает, что регистрация пользователей сейчас может не работать. Это не проверка доступности Codex на компьютерах.

## Доставка и ограничения

Между отправками в один чат минимум 2 секунды для всех подключённых устройств. `retry_after` Telegram учитывается. Сервер не накапливает очередь оповещений офлайн: клиент повторяет запросы только пока уведомление актуально. Уже начатый запрос нельзя отозвать после передачи Telegram.

ID сообщения обеспечивает повтор HTTP-запроса без повторной отправки; запись хранится 24 часа. При неопределённом ответе Telegram или перезапуске посреди отправки результат сохраняется как `unknown`, клиент показывает неопределённость и не засчитывает доставку. Возможен пропуск одного уведомления серии; гарантии exactly-once у Telegram sendMessage нет. Успех означает приём Telegram API, а не прочтение человеком или гарантированный звук телефона.

Тексты уведомлений не записываются в базу или access log. Сохраняются хэши ключей и текстов, Telegram ID/username, имена устройств, статус отправки и offset обновлений. Ключи в открытом виде на сервере не сохраняются. Оператор сервера технически обрабатывает тексты при пересылке.

`/stop` отзывает все устройства только отправителя. Чужие устройства и настройки не затрагиваются. После отзыва нужен новый Start. На этапе разрешения доступа рекомендуется использовать стабильные Telegram ID.

## Проверки

```text
python -B -m unittest discover -s relay -v
```

Тесты не используют реального бота. Проверяются изоляция пользователей, неправильные отправители, привязка ID, истечение ссылок, HTTP-аутентификация, запрет выбора чужого чата, отзыв, интервалы, 429, повтор запроса и восстановление после неопределённой отправки.
